# Organization websites

One Enterprise organization can now operate a website at `/sites/{slug}`. Each website has its own private draft, enquiry inbox, artwork and publication history. Customer names and copy are supplied as onboarding data. A club pilot and an NGO client can use the same renderer in separate workspaces.

## Onboard an organization

1. In **Admin → Organizations**, select the existing organization or create it using the agreed Enterprise plan. Confirm the legal name and invite its actual lead through the existing organization staff flow. An organization lead authorizes publication. Ordinary active organization staff can prepare copy.
2. A platform administrator creates a private draft under **Organization website** and chooses the address. In **Admin → Feature flags**, enable `websites_enabled` for the early-access rollout. This global switch works alongside the individual grant. Website access does not grant any group subscription or create a billing transaction.
3. Open **Enterprise → Website Studio**. Set the headline, introduction, programme descriptions, public contact email and brand accent. The editorial JSON importer accepts the same fields, with a 64 KiB cap. Upload an approved logo or cover image with an accessible description. Images are normalized to WebP, stripped of input metadata and capped at 180 KB each. There are 20 artwork slots per organization. Delete unused artwork to free a slot.
4. Select each eligible Enterprise programme or Changi$ha campaign to feature. Only approved, active group links qualify. The studio labels an unavailable source so editors can remove it. Choose whether to show member sign-in and whether to accept website enquiries.
5. **Save draft** updates the private preview. **Publish reviewed preview** requires an active organization lead and the digest of that exact preview. A stale revision, changed source or different organization invalidates the request. The public address returns 404 until publication. Saving later edits keeps the previous snapshot live.
6. Use the Studio inbox to read and mark enquiries handled. A visitor consents to sharing the email and message for a reply. The inbox sends no SMS or marketing subscription. Staff use the approved reply channel. The default view prioritizes outstanding messages and shows up to 100.
7. **Withdraw public site** removes the publication pointer. Administrators can suspend one grant or disable the global flag. Suspension preserves the reviewed publication for restoration. For an urgent programme or fundraiser correction, withdraw the site, remove the source, and publish a reviewed revision. Old links never authorize an application or a payment.

## Release and operations

Apply migrations 219, 220 and 221 in order. They add website drafts, immutable-by-application publications, private artwork, enquiries and the default-off flag. The server owns table access. RLS denies client access to the tables, and an anonymous reader can call only the website-specific snapshot function for public website content. Media selected at publication is embedded in the snapshot so later asset removal cannot change an approved version. Each publish records its actor and revision in `audit_logs`.

The initial release uses a platform path and dynamic rendering so suspension takes effect on the next request. Newspaper-style editorial text is plain text. The default photograph is illustrative and can be replaced with a consented client image. [Image source record](../../public/img/IMAGE_SOURCES.md)

The local acceptance suite exercises two independent organizations, live membership checks, editor and publisher roles, draft isolation, stale previews, programme and campaign selection, image ownership, form consent, retries, limits and the anonymous database role. Run it on a **disposable migrated** database with `npm run test:integration -- --runTestsByPath __tests__/integration/organization-websites.test.ts`. The suite resets its test data. Keep client drafts in a separate database.

For release rollback, disable the flag and revert the application change while retaining the additive tables and snapshots. Re-enable after verifying the public pointer, staff permissions and inbox in staging. To undo a content change, withdraw, edit the draft and publish again. Retained snapshots provide a record of prior releases.

Before public onboarding, agree the client lead, approved content and photographs, inbox access and retention, the organization's actual linked groups and campaigns, and its public address. Customer domain mapping, commercial website subscriptions, outbound enquiry notifications, multilingual sites, club bundles and a general multipage builder remain separate releases. Pricing and DNS need an owner decision. The local client draft confers no production identity or commercial terms.
